# Módulo 6: Bases de Datos NoSQL y Otras Tendencias y Tecnologías Actuales

## Conceptos clave

- **NoSQL**: Bases de datos no relacionales diseñadas para escalabilidad horizontal, esquemas flexibles y alta disponibilidad, priorizando velocidad sobre consistencia fuerte.
- **Cuatro modelos NoSQL**: Clave-valor (Redis, DynamoDB), Documental (MongoDB, Couchbase), Columnar/Wide-Column (Cassandra, HBase), Grafo (Neo4j, Neptune).
- **Teorema CAP**: En sistemas distribuidos solo pueden garantizarse dos de tres propiedades: Consistencia, Disponibilidad, Tolerancia a particiones.
- **ACID vs BASE**: ACID (Atomicidad, Consistencia, Aislamiento, Durabilidad) para transacciones seguras; BASE (Basically Available, Soft state, Eventually consistent) para disponibilidad y latencia baja.
- **Data Warehouse / OLAP**: Repositorio centralizado para análisis histórico con esquemas estrella/copo de nieve; OLAP permite navegación multidimensional (slice/dice, drill-down, roll-up).
- **ETL / ELT**: Procesos de integración de datos (Extraer, Transformar, Cargar / Extraer, Cargar, Transformar) para unificar fuentes heterogéneas.
- **Big Data (5 V)**: Volumen, Velocidad, Variedad, Veracidad, Valor.
- **MapReduce / Spark**: Paradigmas de procesamiento distribuido; Spark evoluciona a MapReduce con cómputo en memoria y API unificada.
- **Bases distribuidas**: Sharding (fragmentación horizontal), Replication (réplicas para alta disponibilidad), CAP theorem aplicado.
- **Ciencia de Datos**: Ciclo de vida: recolección → limpieza → EDA → modelado → evaluación → implementación/comunicación. Roles: Data Engineer, Analyst, Scientist, ML Engineer, Architect.

## Desarrollo principal

### Parte I: Bases de datos NoSQL

El documento contextualiza el surgimiento de NoSQL a mediados de los 2000 ante la explosión de usuarios web y datos no estructurados (logs, geolocalización, sensores). Las bases relacionales presentan limitaciones: escalabilidad vertical costosa, esquemas rígidos, dificultad con datos no estructurados, rendimiento limitado en operaciones distribuidas y complejidad ante cambios frecuentes de modelo.

**Clasificación NoSQL** con motores, conceptos, ventajas y casos de uso:
- **Clave-valor** (Redis, DynamoDB): acceso O(1), ideal para caché, sesiones, colas pub/sub.
- **Documental** (MongoDB, Couchbase): documentos JSON/BSON en colecciones, esquema dinámico, consultas ricas sin JOINs; perfiles de usuario, catálogos e-commerce, CMS.
- **Columnar/Wide-Column** (Cassandra, HBase): filas con millones de columnas agrupadas en familias, escritura masiva rápida, compresión; series temporales IoT, click-stream, contadores distribuidos.
- **Grafo** (Neo4j, Neptune): nodos + relaciones + propiedades, recorridos en O(aristas); redes sociales, recomendaciones, detección de fraude, RBAC/ACL.

Incluye ejemplos prácticos de modelado y consultas en Redis (CLI), MongoDB (shell), Cassandra (CQL) y Neo4j (Cypher).

**Teorema CAP**: Explicación detallada de las tres propiedades y los tres trade-offs posibles: CA (imposible en práctica), CP (bancos, contabilidad — MongoDB/HBase modo fuerte), AP (redes sociales, carritos — Cassandra, DynamoDB, Couchbase). Analogías: cajero automático (CP) vs local que vende offline (AP).

**Consistencia Eventual vs ACID**: Definición de las cuatro propiedades ACID con ejemplo de transferencia bancaria. Principio BASE como alternativa: Basically Available, Soft-state, Eventually consistent. Ventaja: disponibilidad y latencia baja; coste: "vista borrosa" temporal.

**Data Warehousing y OLAP**: DW como repositorio centralizado, orientado a temas, integrado, no volátil, variable en el tiempo. Componentes: ETL, almacén (estrella/copo), metadatos, herramientas de acceso. Tipos OLAP: MOLAP (cubos precalculados), ROLAP (SQL sobre DW), HOLAP (híbrido). Casos de uso: reportes gerenciales, tendencias, segmentación. Resumen flujo: ETL → DW → Cubo OLAP → Dashboard.

### Parte II: Integración, Big Data y Ciencia de Datos

**Integración y ETL/ELT**: Datos dispersos en sistemas OLTP, hojas de cálculo, APIs, logs, IoT, plataformas externas. Fases ETL: Extract (conectores a BD, APIs, archivos, streaming), Transform (limpieza, conversión, homologación, enriquecimiento, validación, reglas de negocio), Load (DW, Data Lake, Data Mart, bases analíticas cloud). Modalidades: completa/incremental, batch/streaming. Herramientas: tradicionales (Pentaho, Talend, Informatica), orquestadores modernos (Airflow, Luigi, Prefect), Python ligero (pandas, sqlalchemy), cloud (AWS Glue, Azure Data Factory, Google Dataflow). Diferencia ETL (transforma antes de cargar) vs ELT (carga primero, transforma en destino).

**Big Data**: Definición más allá del tamaño: complejidad de procesamiento y extracción de valor. Las 5 V con descripción y ejemplos. Arquitectura general. **MapReduce** (Google 2004, Hadoop): fases Map, Shuffle, Reduce; ventajas (escalabilidad horizontal, tolerancia a fallos), limitaciones (overhead disco, no tiempo real). **Apache Spark**: evolución in-memory, 10-100x más rápido, API unificada (SQL, streaming, ML, gráficos), lenguajes Python/Scala/Java/R. Módulos: Core, SQL, Streaming, MLlib, GraphX.

**Bases de datos distribuidas**: Conceptos sharding, replication, consistency, partition tolerance, CAP. Ejemplos: HBase (columnar sobre HDFS), Cassandra (peer-to-peer, AP), MongoDB Sharded Cluster (documental, shards por rango/hash), Elasticsearch (búsqueda distribuida, shards/réplicas).

**Ecosistema moderno Big Data** por capas: Ingesta/ETL (Kafka, NiFi, Airflow), Almacenamiento (HDFS, S3, Delta Lake, Iceberg), Procesamiento batch (Spark, Flink, Hadoop), Streaming (Kafka Streams, Spark Streaming), Consulta interactiva (Hive, Presto, Dremio, BigQuery), Analítica avanzada (Spark MLlib, TensorFlow, PyTorch), Visualización (Kibana, Superset, Power BI).

**Ciencia de Datos**: Disciplina interdisciplinaria (estadística/matemática, programación, conocimiento del dominio). Objetivo: extraer conocimiento, predicciones, decisiones basadas en evidencia. Ciclo de vida: recolección (SQL, NoSQL, APIs, sensores, scraping) → limpieza/preparación (pandas, OpenRefine, SQL, Airflow) → EDA (matplotlib, seaborn, Power BI, Kibana) → modelado (scikit-learn, XGBoost, TensorFlow) → evaluación (métricas según problema: accuracy/precision/recall/F1, RMSE/MAE/R², silhouette/inertia) → implementación/comunicación (Flask, FastAPI, Streamlit, Dash, Grafana, Power BI).

**Rol de los sistemas de datos**: Infraestructura fundamental. Fuentes (OLTP, IoT, open data) → Integración (ETL/ELT, Airflow, Kafka, Spark) → Almacenamiento según tipo (SQL relacional, NoSQL documental, Data Lake, búsqueda distribuida) → Procesamiento (batch/streaming) → Explotación (BI, ML, Data Science avanzada). Roles con enfoque y herramientas clave: Data Engineer, Data Analyst, Data Scientist, ML Engineer, Data Architect.
