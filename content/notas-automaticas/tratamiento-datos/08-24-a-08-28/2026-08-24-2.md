# Sistemas de tratamientos de datos  

**Conceptos clave**  
- **Sistema de archivos**: organización jerárquica de archivos en un medio de almacenamiento (ej. NTFS, ext4, APFS).  
- **SGBD (Sistema de Gestión de Bases de Datos)**: software que permite definir, crear, mantener y controlar el acceso a una base de datos estructurada (ej. MySQL, PostgreSQL, Oracle, SQL Server).  
- **Redundancia de datos**: almacenamiento múltiple de la misma información.  
- **Inconsistencia de datos**: existencia de versiones diferentes del mismo dato debido a actualizaciones parciales.  
- **Integridad de datos**: cumplimiento de reglas y restricciones (claves primarias, foráneas, dominio, etc.).  
- **Concurrencia**: acceso simultáneo de varios usuarios o procesos a los mismos datos.  
- **Propiedades ACID**: Atomicidad, Consistencia, Aislamiento, Durabilidad.  
- **Componentes de un SGBD**: Gestor de datos, Procesador de consultas, Diccionario de datos, Gestor de almacenamiento, Subsistema de recuperación, Subsistema de seguridad y autorización, Interfaces de usuario y aplicación.  

**Desarrollo principal**  
El documento compara los sistemas de archivos tradicionales con los SGBD, señalando que, aunque ambos almacenan información digital, difieren en estructura, funcionalidad y ventajas. Los sistemas de archivos presentan problemas de redundancia, inconsistencia, dificultad para mantener la integridad, conflictos de concurrencia, seguridad limitada y acceso ineficiente a datos complejos. Estos inconvenientes motivan la adopción de SGBD, que ofrecen abstracción de datos, modelos de datos definidos, independencia de datos, gestión de concurrencia mediante bloqueos y transacciones ACID, control de integridad mediante restricciones, seguridad granular (roles, permisos a nivel de fila/columna), mecanismos de recuperación y acceso eficiente mediante índices y lenguajes declarativos como SQL. Posteriormente se describen los seis subsistemas principales de un SGBD y sus funciones: gestión de datos, procesamiento de consultas, diccionario de datos, gestión de almacenamiento, recuperación de fallos, seguridad y autorización, y las interfaces de usuario y aplicación que permiten la interacción con el sistema.  

**Conclusiones**  
Los SGBD son la opción superior cuando se requieren alta integridad de datos, concurrencia, seguridad granular, acceso eficiente a datos estructurados y complejos, reducción de redundancia e inconsistencia, y tiempos de desarrollo más cortos gracias a funcionalidades compartidas entre aplicaciones. Los sistemas de archivos siguen siendo adecuados para datos no estructurados o poco relacionados y para aplicaciones simples donde su simplicidad y bajo costo son suficientes.
