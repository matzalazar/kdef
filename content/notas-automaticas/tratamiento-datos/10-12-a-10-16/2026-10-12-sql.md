**Conceptos clave**  
- **DB Browser for SQLite**: herramienta visual y liviana para trabajar con archivos .db de SQLite, disponible en versión instalable y portable.  
- **sqliteonline.com**: editor en línea que permite ejecutar SQL sin instalar motores, pero limita la cantidad de consultas diarias.  
- **MariaDB (servidor local)**: SGBD que se ejecuta como servicio de Windows y se conecta mediante clientes gráficos (DBeaver, HeidiSQL, Beekeeper Studio).  
- **Persistencia**: en SQLite los datos se guardan en un archivo .db local; en MariaDB residen en el servidor.  
- **Sensibilidad a mayúsculas y minúsculas**: el operador `=` en SQLite es case‑sensitive; para búsquedas insensibles se usa `LIKE`.  
- **Funciones de fecha en SQLite**: no existen `YEAR()` ni `MONTH()`; se emplea `strftime('%Y', fecha)` y `strftime('%m', fecha)`.  
- **Operadores ANY y ALL**: no implementados en SQLite; se reemplazan por combinaciones de `IN/NOT IN` y `MIN/MAX` según las equivalencias mostradas.

**Desarrollo principal**  
El documento presenta tres alternativas para practicar sentencias SQL de forma interactiva:

1. **DB Browser for SQLite**  
   - Descarga desde sqlitebrowser.org (instalador estándar o versión portable).  
   - Instalación en Windows: aceptar licencia, marcar accesos directos, finalizar.  
   - Uso: crear una nueva base de datos (.db), ejecutar scripts SQL en la pestaña *Ejecutar SQL* (F5 o botón ▶), guardar tanto el archivo .db como el .sql, visualizar estructura y datos mediante las pestañas *Estructura de la base de datos* y *Explorar datos*.  
   - Particularidades de SQLite: sensibilidad a mayúsculas/minúsculas, uso de `strftime` para extraer año/mes, falta de operadores ANY/ALL con sus equivalencias.

2. **sqliteonline.com**  
   - Acceso vía navegador; permite elegir entre SQLite, MariaDB, PostgreSQL y SQL Server.  
   - Incluye una tabla de demostración “demo” que puede eliminarse.  
   - Limitación: el sitio restringe el número de consultas diarias, por lo que se recomienda solo para pruebas rápidas, no para trabajos prácticos extensos.

3. **MariaDB (servidor local)**  
   - Instalación mediante .msi desde mariadb.com/downloads (MSI Package, 64‑bit).  
   - Durante la instalación se define la contraseña de root, se deja el puerto 3306 y se habilita el servicio de Windows.  
   - Verificación del servicio en *Inicio → Servicios* (estado “En ejecución”).  
   - Conexión desde clientes gráficos (DBeaver, HeidiSQL, Beekeeper Studio) usando: Host = localhost (o 127.0.0.1), Puerto = 3306, Usuario = root, Contraseña = la establecida.  
   - No se detalla la instalación de cada cliente; se sugiere elegir uno y consultar su documentación.

**Conclusiones**  
Para realizar las prácticas de la materia basta con seleccionar la alternativa que mejor se ajuste al equipo y al nivel de comodidad con la instalación de programas. DB Browser for SQLite es la opción más sencilla y portátil; sqliteonline.com sirve para pruebas rápidas pero tiene límites de uso; MariaDB ofrece un entorno de servidor completo semejante al de producción, requiriendo una instalación más involucrada pero permitiendo trabajar con múltiples clientes gráficos. En todos los casos es recomendable guardar tanto el archivo de base de datos (.db) como el script SQL (.sql) para poder reconstruir el trabajo desde cero si fuera necesario.
