# SQL Básico – Alternativas Entornos Interactivos  

**Conceptos clave**  
- **DB Browser for SQLite**: herramienta visual y portable para trabajar con archivos .db de SQLite.  
- **sqliteonline.com**: editor en línea que permite consultar distintos SGBD (SQLite, MariaDB, PostgreSQL, SQL Server) con límite diario de consultas.  
- **MariaDB (servidor local)**: SGBD que se instala como servicio de Windows y se accede mediante clientes gráficos (DBeaver, HeidiSQL, Beekeeper Studio).  
- **DDL / DML**: lenguaje de definición y manipulación de datos usado para crear tablas y ejecutar consultas.  
- **Persistencia**: en SQLite los datos se guardan en un archivo .db local; en MariaDB residen en el servidor.  
- **Sensibilidad a mayúsculas**: en SQLite el operador `=` es case‑sensitive; para búsquedas indistintas se usa `LIKE`.  
- **Funciones de fecha en SQLite**: no existen `YEAR()` ni `MONTH()`; se emplea `strftime('%Y', fecha)` y `strftime('%m', fecha)`.  

**Desarrollo principal**  
El documento presenta tres alternativas para practicar sentencias SQL de forma interactiva:  

1. **DB Browser for SQLite** – se detalla la descarga e instalación (versión estándar o portable) en Windows, los pasos para crear una nueva base de datos, ejecutar scripts SQL (guardando tanto el .db como el .sql), visualizar la estructura y los datos, y guardar cambios con Ctrl + S. Se añaden particularidades de SQLite: sensibilidad a mayúsculas y el uso de `strftime` para extraer año y mes de una fecha.  

2. **sqliteonline.com** – herramienta web que no requiere instalación; permite seleccionar entre varios motores de base de datos. Se advierte que el sitio impone un límite diario de consultas, por lo que es adecuado solo para pruebas rápidas y no para trabajos prácticos extensos.  

3. **MariaDB (servidor local)** – se describe la instalación mediante un instalador .msi, la configuración de la contraseña de root, el puerto 3306 y la opción de instalar el servicio de Windows. Tras la instalación, se indica cómo comprobar que el servicio está en ejecución y los parámetros de conexión (localhost, puerto 3306, usuario root, contraseña elegida) para conectarse con clientes gráficos como DBeaver, HeidiSQL o Beekeeper Studio.  

En todas las opciones se recomienda guardar tanto el archivo de base de datos como el script SQL para poder reconstruir el entorno si fuera necesario.  

**Conclusiones**  
Para realizar las prácticas de la materia basta con elegir la alternativa que mejor se ajuste al equipo y al nivel de comodidad con la instalación de programas. Cada opción tiene ventajas y limitaciones: DB Browser for SQLite es liviano y portátil; sqliteonline.com es inmediato pero restringido por consultas diarias; MariaDB ofrece un entorno de servidor más cercano a un entorno productivo, aunque requiere instalación y configuración. Independientemente de la herramienta seleccionada, es fundamental guardar los scripts y los archivos de base de datos y tener en cuenta las particularidades de sintaxis de cada motor (por ejemplo, el uso de `LIKE` y `strftime` en SQLite).
